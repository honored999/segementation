## Resource and source boundaries

Check mode constructs no neural model and no CUDA context, reads no patient image/lesion arrays, and creates no output. It audits source metadata, target caches and provenance, including old checkpoint byte hashes. --gpu is optional in check (telemetry only), required physical index in train. UUID is bound before CUDA initialization. Before models and EACH step, reused CPU/RAM/selected-GPU guard plus all-GPU compute/VRAM checks require <80%, >=12GiB free VRAM and >=8GiB free RAM by default. These are configurable minimum headrooms, not predicted model peaks. An additional PyTorch caching-allocator ceiling of79%-initial occupied VRAM is applied; it does NOT cover other processes, non-PyTorch allocations or guarantee peak safety. Peak of native full-width higher-order GPU chain remains UNMEASURED locally. GPU-specific double backward remains untested locally.

A later guard can observe this process's previous kernels as >=80% and refuse. There is no infinite cooldown, cancellation or interference with concurrent offline training. One-step pilot is the intended first use. Resource refusal before output creation leaves no output; failures after output creation preserve an incomplete directory. Partial in-memory copies on hardware/process failure are not crash-transactional; ordinary numerical/functional exceptions occur before live commit, as tested.
